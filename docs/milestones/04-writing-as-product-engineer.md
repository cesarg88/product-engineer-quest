# Milestone 4 — Writing as a Product Engineer

## Objective

Learn to write short documents that help teams make better decisions.

## Competencies Trained

Primary:

- Leadership Without Authority
- Product Thinking

Secondary:

- Business Thinking

## Why This Matters

Product-oriented engineers influence through clarity. A strong short document can align product, design, backend, data, and mobile without requiring formal authority.

## Tools Needed

- GitHub repository
- ChatGPT as editor/reviewer
- Templates for RFCs, decision notes, and trade-off notes

## Exercises

Write 3 short documents:

1. RFC: Improve Favorites discoverability
2. Decision note: Where should Favorites live?
3. Trade-off note: Save for later vs Favorites

Each document should include:

- context;
- problem;
- options;
- recommendation;
- risks;
- metrics.

## Deliverables

- `journal/rfcs/01-improve-favorites-discoverability.md`
- `journal/decision-notes/04-where-should-favorites-live.md`
- `journal/trade-offs/01-save-for-later-vs-favorites.md`

## Completion Criteria

This milestone is complete when the player can write a one-page recommendation that is clear, structured, and useful to non-technical stakeholders.

## Feedback Loop

Each document receives feedback on clarity, structure, reasoning, and stakeholder usefulness.
